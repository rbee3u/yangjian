# Source provenance is graded; registry claims alone are never a source match

Source provenance claims will carry an explicit level: P0 registry claim (an explorer or registry says verified), P1 metadata binding (the on-chain solc metadata pointer ties runtime bytecode to source hashes and build settings), P2 reproducible build (local recompile matched after masking immutables and constructor arguments), and P3 full reproducibility (source maps and complete build artifacts). The MVP requires P1 when a metadata pointer exists; contracts whose metadata sets `bytecodeHash: none`, including the Uniswap V3 Factory, Pool, and NonfungiblePositionManager, go directly to P2 because P1 is unreachable. If P2 also fails, the claim is recorded as P0 with an explicit unproven-correspondence marker, never as a source match. Critical contracts target P2, and P0-only claims are never presented as proof of deployment correspondence.
