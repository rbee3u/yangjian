# M2 discovers topology in evidence order and stops at an explicit budget

M2 builds relations in evidence order: registry seeds first, then pinned on-chain reads (`getPool`, `factory()`, `token0()`, `token1()`), then optional source constants, bounded factory events, pinned GitHub/npm deployment artifacts, and heuristics. The current implementation stops after the pinned on-chain reads and selects a fixed four-role topology (factory, pool, NonfungiblePositionManager, router); later layers are deferred. Each step writes the matching relation type, and no `observed_call` relation is produced without a trace. Exploration is bounded to max 50 contracts and max 1000 requests per dossier; `budgets.max_depth` is reserved for recursive discovery, and the current role selection does not recurse. Exceeding a budget stops discovery and records an open question. Without these layers M2 would either miss dynamically created contracts or mistake static references for execution; without budgets the agent can recurse indefinitely.
